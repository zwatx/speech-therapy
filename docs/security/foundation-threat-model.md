# Foundation threat model

Status: engineering draft; independent review required before Gate 1

The evidence-routing endpoint now requires a separate 32-byte-or-longer
service credential and rejects learner-supplied probability claims. The
`/api/v1` consent, device-session, export, and deletion boundaries require Clerk
identity, an active organization, internal membership resolution,
tenant-scoped queries, bounded JSON, and no-store responses once providers are
configured. No surface is approved for patient data or internet exposure yet.
The current browser mutation CSRF control is the strict `application/json`
requirement: cross-origin JSON requires a preflight, and no route emits a
permissive CORS response. This requirement must not be loosened without an
explicit Origin or anti-CSRF-token control.

## Protected assets

- Child voice, face video, derived landmarks, attempt evidence, and clinical context.
- Caregiver consent/assent records and deletion/export requests.
- Clinician identity, tenant membership, assignments, overrides, and audit events.
- Model, threshold, target-protocol, and feedback-template release integrity.

## Primary threats and required controls

| Threat | Status in this foundation | Required control before Gate 1 | Gate 1 evidence |
| --- | --- | --- | --- |
| Cross-clinic record access | Partially implemented: organization-bound identity mapping, role-aware resource authorization in every page/API/Server Action, tenant-scoped prepared statements, audited learner reads, and negative tenant/role tests exist; provider provisioning and database-enforced isolation do not. Proxy path matching is never the sole authorization gate. | Use a non-owner application role, database tenant policies, and verify resource authorization against the deployed identity/database roles. | Negative authorization integration tests against the deployed role and independent review. |
| Child account takeover | Partially implemented: clinician-issued random device tokens are stored only as hashes, expire within 72 hours, bind to the latest consent snapshot, and are held in this-device-only Keychain storage only after the server authenticates them. Devices fetch an immutable consent-bound dose without supplying a learner ID; every attempt must match the latest assignment ID, exercise, repetition, and retry slot. Consent or assignment supersession fails closed. Owners/clinicians can inspect every active grant plus bounded inactive history and explicitly revoke access; the database transition is idempotent, records one audit, and prevents every later assignment fetch or attempt while exposing no token/hash. A partial unique index enforces five live slots per learner; atomic rotation transfers one slot from the old token to a one-time replacement and rolls back completely if insertion/auditing fails. Issuance and rotation share durable fixed-window limits of 10 generations per learner and 30 per clinician actor per UTC hour; capacity conflicts count, internal slot retries count once, blocked HTTP responses include `Retry-After`, and emergency revocation remains available. Rate buckets contain opaque IDs and counts only, and learner rows are deleted with the learner; bounded automatic retention remains open. Lost-response recovery is explicit. Already-authorized in-flight work is not claimed to be cancelled. Tokens and transient attempts are deleted with the learner; immutable assignment history is disclosed as retained deletion evidence. | Add learner-device invalid-token/IP and provider-edge throttling, aggregate-bucket retention operations, managed transport/log inspection, provider-role verification, real PostgreSQL/Neon migration and concurrency proof, and independent mobile-boundary review. | Deployed grant issuance/rotation/revocation, migration/backfill, slot-collision and revoke-versus-request concurrency, assignment-substitution/dose-overflow, rate-limit/window-boundary/contention, lost-response, network-capture, and mobile security tests. |
| Media URL leakage | Partially implemented: raw PCM uses a bounded direct request under a short-lived device grant; no media URL or storage object is created, the database enforces `media_retained = FALSE`, and iOS deletes temporary files after every outcome. Valid sessions have independent database-backed UTC-hour budgets of 120 assignment reads and 120 attempt uploads; authorization rechecks the live exact-consent grant, private `429` responses carry `Retry-After`, and the native client preserves calm retry guidance. Invalid tokens create no bucket. | Verify infrastructure logs/body capture, add trusted invalid-token/IP edge limits, rehearse migration 0025 and contention on managed PostgreSQL, and test interruption/crash cleanup on real devices. | Network capture, storage inspection, expiry/rate-limit/UTC-rollover tests, managed contention evidence, and access-log alerting. |
| Consent mismatch | Partially implemented: Postgres stores immutable snapshots; device sessions and append-only derived attempts bind to the exact latest snapshot. The tenant attempt-review queue and learner detail expose capture evidence only when the attempt is bound to the exact current snapshot with clinician review enabled; even a benign consent renewal redacts older evidence, and authorized/empty reads are audited. Research artifacts inherit exact consent lineage. Supersession/deletion transactionally quarantines every descendant and creates subject-specific purge/disable/retrain/re-evaluate actions. Tenant-scoped health monitoring, local alert evidence, and conservative deletion-drill reports detect overdue, expired, unresolved, and dead-letter work. A provider-neutral Ed25519 verifier and append-only tenant public-key registry fail closed on tampering, invalid windows, unregistered/revoked keys, and stale trust, but only ephemeral private test keys exist and no alert is delivered. | Connect reviewed provider adapters and authenticated scheduling, provision KMS/HSM custody and key ceremony/dual control, and deliver/acknowledge alerts in the managed environment. | Provider-backed signed revocation receipts, deployed review-query authorization tests, witnessed key-rotation/emergency-revocation drill, alert delivery/acknowledgement, historical audit, and deletion drill. |
| Model/config tampering | The first benchmark checkpoint, upstream revision, runtime, vocabulary, and model hashes are pinned; signing and release controls do not exist. | Make releases immutable, signed, permissioned, and feature-flagged by target and population. | Registry permissions, signature verification, and rollback drill. |
| Artifact-store drift | Partially implemented: privacy-safe provider/object-reference hashes bind immutable artifact digests and versions; append-only local observations detect missing objects, digest drift, and access-state mismatch against current quarantine state. No raw locator, authenticated provider adapter, or signed observation is present. | Provision separately authorized locator custody and a reviewed provider adapter with signed observations, schedules, alerts, and least-privilege access. | Provider-backed digest/access reconciliation, locator-access review, tamper drill, and alert evidence. |
| Unauthorized research job | Partially implemented: append-only job envelopes bind exact consent-authorized inputs and managed-object evidence to code/config/container provenance, legal output transitions, expiry, and distinct review. A governed scheduler signs expiring revisioned assignments for an exact envelope and runner. A separate registered provider workload signs one launch per dispatch, binding the requested image plus hashed process, execution-identity, and network-policy evidence; the gate-resolved launch is stored on the immutable v2 runner claim, and heartbeats must retain its process hash. The same provider workload can sign external stop evidence for the exact launch/process and current effective cancellation; a launched cancelled terminal requires both runner acknowledgement and provider stop attestation. A separate alert workload signs delivered receipts for exact alert-required liveness snapshots using canonical state and hashed channel/receipt references. Shared trust/job gates reject reassignment/relaunch races, expiry, substitution, scheduler/runner/provider revocation, replay, cancellation escalation, and duplicate claims. Registered-key verification does not prove provider-native key custody or that a cloud launch/stop/IAM/network/alert action occurred; private keys are ephemeral tests, no approved alert destination exists, and no cloud adapter or managed IAM exists. | Provision KMS/HSM workload keys and least-privilege roles; connect launch and termination boundaries to one reviewed provider API and provider-native identity evidence; connect alert attestations to an approved destination registry and real sender. | Managed scheduler/runner/provider signature, launch/stop, expiry, revocation and concurrency tests; independent launch/liveness/termination evidence; alert delivery/escalation; lineage outputs; IAM audit. |
| Unsupported feedback | Partially implemented: benchmark evidence remains forced ambiguous/uncalibrated and never returns correction. A candidate-only canonical research simulator binds exact static copy and claim kinds to recomputed routes, registry/threshold hashes, retry limits, per-attempt cue state, stop/distress escalation, population, a 15-minute lease, and an exact nine-scenario sample hash. Its bounded audit reports detected policy violations; learner and production eligibility are hard false. | Verify platform-signed SLP, model, usability, accessibility, utility, and governance evidence; persist current release/session state; connect clinician review/rollback only after the target and population pass. | Locked real release samples produce a zero-finding independent clinical audit; runtime proves no unapproved template, cue, retry, population, revoked evidence, or expired release was shown. |
| Third-party tracking | Implemented: no advertising, session replay, or behavioral analytics SDK is installed. The current MediaPipe Tasks runtime was not embedded after its official privacy notice disclosed performance/utilization metrics sent to Google; the local visual feasibility slice uses Apple Vision without a third-party SDK. | Preserve the prohibition across authenticated and learner surfaces. Require a documented telemetry disposition, processor review, and consent analysis before adding MediaPipe or another vision SDK. | SBOM/vendor audit and physical-device network-capture verification. |
| Insider access | Partially implemented: membership roles, append-only audit events, and privileged export/deletion logs exist; provider operations and monitoring do not. | Provision least-privilege provider/database roles, immutable log export, alerts, and periodic access review. | Access review, alert test, and incident exercise. |

## Explicit exclusions

Facial identity, emotion inference, passive/background recording, advertising,
and unsupervised online learning are outside the product boundary.
