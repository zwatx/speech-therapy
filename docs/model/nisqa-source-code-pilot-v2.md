# NISQA source-code ingestion pilot v2

September 27, 2026; declared before selecting files, inspecting quality values or acquiring audio. This extends the [original ingestion protocol](nisqa-training-ingestion-protocol.md) and [transport correction](nisqa-discovery-transport-v2.md). It changes the provenance-group claim and allows waveform ingestion before the unresolved score-definition audit. It preserves the 20-file quota, selection salt/order, byte limits, recording inclusion rule and prohibition on fitting/performance claims.

Independent Astra post-discovery review found that intended publisher/DNS reader-number codes are adequate for an ingestion-only sample, while they do not prove 20 distinct human readers. The [official DNS source discussion](https://github.com/microsoft/DNS-Challenge/issues/24#issuecomment-759886398) describes book, chapter and reader numbers. A separate [reader-ID discrepancy report](https://github.com/microsoft/DNS-Challenge/issues/51) is unresolved. Keep codes as approximate provenance labels, never as audited people or proof of speaker-independent validation. This explicitly revises the original acceptance wording; it does not claim that wording has been satisfied.

Use only the pinned 1,020-row opaque TRAIN_LIVE lineage inventory. Source must be DNS, language English, degraded filename must equal the canonical path basename, and the source reference path must exactly match its safe reference basename. Derive book/chapter/reader-number/segment codes from the publisher's explicitly named reference-file components, using one declared anchored grammar. Validate degraded filename/reference correspondence. Capture category comes from the actual publisher `con_description` strings Skype or VoIP-landline to mobile and must agree with its suffix; do not infer capture from scores. Report any schema failures without substituting new files.

Preserve complete source-reference/book/chapter/segment lineage and original approximate reader codes. Group by the approximate DNS reader-number code across books/chapters. Conservatively merge groups sharing an exact source-reference identifier before selection; preserve merged membership. This check does not detect unknown duplicate content or prove correct human-reader mapping. No score, vote count, standard deviation, audio statistic or model prediction may affect selection.

Freeze exactly 20 training identities from 20 distinct resulting **source-code groups**, 10 phone and 10 Skype. Reuse the original deterministic selector: phone then Skype, exclusive-condition groups before shared groups, the fixed salt `cadence-nisqa-train-live-ingest-v1`, and SHA256(group/file) ordering with the existing NUL namespaces and identifier/path tie breakers. Preserve complete eligibility and grouping evidence, including condition/group support and all exclusions, before any audio/score access. Insufficient support fails without replacement.

After independent implementation review, audio acquisition/waveform audit can proceed for exactly these frozen 20 identities with the existing persistent ledger, official archive, exact member allowlist, CRC/size/SHA checks and cumulative 256 MiB limit. Score parsing remains deferred until an explicit justified five-column range/direction/missingness declaration exists. Keep that unresolved dependency visible. Audit all selected files without outcome-based exclusion, normalization, replacement or silent restart. No validation/test audio or evaluation numeric targets may be used.

Pilot success still requires honest acquisition/waveform/metadata joins and the score-definition audit; source-code grouping alone does not complete it. It does not establish 20 independent people, child applicability, prediction improvement, a usable rejection threshold or permission for learner judgments. Later model evaluation needs a stronger speaker/content-disjoint design than these approximate codes alone. No GPU allocation or model fitting is authorized by this ingestion plan.
