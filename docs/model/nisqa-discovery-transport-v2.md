# NISQA discovery transport correction v2

Declared before any archive-member body acquisition. This extends the unchanged [training ingestion protocol](nisqa-training-ingestion-protocol.md); it changes HTTP validator handling only. Directory, metadata, identity and target/audio boundaries and all quotas, selection rules and budgets remain as declared there.

The first v1 attempt stopped before reading the first range body: HEAD supplied Last-Modified but the HTTP206 response supplied neither Last-Modified nor ETag. Its immutable failure, source review, ledger and request journal are bound as v2 inputs. The old ledger records zero transferred body bytes, zero uncertain bytes and zero reservations; a fresh v2 ledger is permitted only while those counts remain zero. There is no discarded spending or full-archive fallback.

[HTTP Semantics RFC9110 §15.3.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7) allows omission of other representation headers when replying to If-Range because the client already has them. Requiring Last-Modified in every such206 response incorrectly rejects this server behavior. A206 response still must supply ETag if it would have supplied one in200.

The corrected transport uses a strong, syntactically valid HEAD ETag when present and requires that same ETag on partial responses. A weak or malformed HEAD ETag is rejected; it cannot fall back to a date. Without any ETag, HEAD must provide valid timezone-aware HTTP Date and Last-Modified fields with Date at least60seconds later. This60second gap is our conservative clock-uncertainty policy; [RFC9110 §8.8.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.2.2) specifies at least one second plus reason to believe the clocks agree or enough difference to make synchronization issues unlikely. Preserve actual HEAD Date and gap evidence in the journal; Date may advance on reopening without changing archive identity.

Every range sends the pinned strong If-Range validator. Only exact206, Content-Range endpoints/total and Content-Length, with identity encoding and the original HTTPS URL, can precede body reads. Any conflicting supplied ETag or Last-Modified fails; missing Last-Modified is allowed. Missing response ETag fails in ETag mode. In date mode an unexpected response ETag fails conservatively. Record actual response headers, never synthesized values. The date mode depends on correct server enforcement of If-Range; it is not a cryptographic archive-wide hash. Member CRC/size and localSHA256 checks remain required, and the advertised full archiveMD5 remains unverified.

Use independent source review and focused transport/integration tests before the first v2 range. Only directory, metadata and identity discovery are covered by this version, not selected20 target/audio stages. Keep historical modules, protocol and artifacts unchanged. No model fitting, GPU use, quality-score performance claim or learner behavior change occurs here.
