## Behavior

Opening/listening, a recognizer result, a first-round recording, denied/invalid capture or skipping cannot create a history entry. Retaking does not erase the fact that a valid manual take occurred, but unresolved recording/permission/check/cleanup blocks finishing.

Finish is explicit. The coordinator snapshots only UUID/date/existing soundID/count1, cleans media through the same feedback owner, then synchronously writes through the unchanged participation store. Private or public deletion failure saves nothing and keeps the visit active. A failed write reports Practice not saved and permits a retry with the identical UUID/time/category/count while the same visit is owned. The store deduplicates UUIDs even if a writer persisted before reporting failure. Finished visits cannot capture/check again through either the coordinator or direct feedback owner. Returning/recheck/end/background/context drift cannot automatically save or retry an abandoned visit. No save is claimed between successful cleanup and a failed/crashed write.
