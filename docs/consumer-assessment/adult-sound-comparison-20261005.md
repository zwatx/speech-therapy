# Local adult sound comparison

The sound comparison adds an explicit **Check sound** action to recording and replay. It is a local engineering preview for adults trying the app, available for **bread** in free practice. It compares the whole recording against BR, BW, BL and a version without the R. It can return a model preference or no clear pick. It does not establish the sound spoken, pronunciation correctness, child validity or a diagnosis.

## Trying it

Use the [local sound app](http://127.0.0.1:8788/); the earlier service at 8782 and its native word-check client remain available. Select **Practice bread**, leave the child-age field unset, select **I'm an adult trying out this app** and **Compare sounds on this computer**, then record a fresh try. Choose **Check sound** only after stopping. Recording and playback do not run this model automatically. Changing either box clears held tries; each declared capture can be checked once.

The adult box describes the requested test context. It does not verify age or establish participant consent. Word check has separate settings. Sound results do not change guided word-check results, counts or progression.

## Feedback and cleanup

An observed result says **Model's best fit: BR/BW/other version**. The limitation appears in the same size and dark ink as the result text. No scores, correction, treatment, diagnosis or progress judgment are shown. We have not checked this against independently confirmed real W/L/no-R examples for bread. Licensed example and generated-signal engineering runs establish execution only.

The browser holds up to two temporary tries. Choosing Check sound sends a separate temporary copy to this computer. Confirmed cleanup deletes its processing audio; private processing diagnostics may remain. If cleanup is uncertain, the private stage is retained for investigation and both sound and word processing pause. Record and Replay remain usable. Ordinary reset or cancellation does not clear that pause.

Results clear when recording again, changing words/settings, clearing tries, entering guided mode, or leaving the page. A late response cannot restore an old result. Hidden-page handlers were tested in controlled source checks; an actual hidden event was not demonstrated in the in-app browser.

## Local implementation

The additive package is [assessment-consumer-sound-app](../../research/assessment-consumer-sound-app/README.md). Startup requires an explicit new port/runtime, exact reviewed external worker artifact/source/receipt, checkpoint cache and feature hash. The old port 8782 is refused. The artifact location is derived from its frozen source map and must match exactly; copying a few matching metadata files elsewhere is rejected. This checkout layout is required, so this is not a portable distribution or public deployment.

One original executor owns both kinds of processing. Source, prompt, request, capture and current-context bindings are checked through cleanup. The model receives samples only, never the prompt. Source and cached runtime policies remain frozen; no fitting, tuning or alternate encoder is added. Numeric posterior scores, decoded phones, process identities and local paths stay out of public responses. All seven eligibility/clinical claim flags remain false.

The owned validation service was closed after confirmed cleanup; its diagnostics remain private. A fresh user-facing service on 8788 runs the same reviewed app with a separate new runtime and no automatic processing. The earlier app on 8782 remains unchanged. Browser handoff initially showed all checking off; subsequent page state contained a selected child age, which correctly disabled the adult preview. No agent microphone/camera/Record action or owner-audio inspection was performed in that handoff. Clear the child-age selection yourself before choosing the adult sound preview; changing settings clears held tries.
