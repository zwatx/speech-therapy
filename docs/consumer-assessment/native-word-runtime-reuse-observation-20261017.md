# Native word runtime reuse: actual model observation

The fixed simulator run completed four public-audio word checks successfully. One encoder/decoder pair served bread, bread and banana; after an awaited idle release, a different pair served bread again. All four receipts matched their requests, confirmed cleanup, and permitted the producer to remove its own temporary file. The three bread checks produced the same completed-text digest. These observations support functional runtime reuse on this tested route.

This was one instrumented Release test on the iPhone SE (3rd generation), iOS 26.5 simulator. It used the ordinary provider and real bundled Core ML worker with explicitly bound resources, rather than the ordinary bundle factory or the guided interface. The canonical worker contains no measurement observer. The two existing Wikimedia public examples and attribution were used locally; no participant recording, microphone or camera was involved.

Four encoder predictions and twelve decoder predictions returned, all off the main thread. Each request performed resource admission. The first pair's wrapper was destroyed before the idle-release acknowledgement; the second pair's wrapper was destroyed before the final-release acknowledgement. These events observe application-owned references, not internal Core ML object destruction or guaranteed operating-system reclamation.

The main-thread heartbeat continued throughout the run: 69 observations, maximum observed gap about 107 ms. Each encoder prediction and both decoder loads overlapped heartbeats. Both short encoder loads and six short decoder predictions had no overlapping heartbeat, so responsiveness within those individual intervals is unestablished. This observation does not qualify complete interface responsiveness or physical-device performance.

Own-process resident-memory snapshots were about 222 MiB before provider creation, 679–687 MiB after recognition, 282 MiB after idle release, and 282 MiB after final release. These are snapshots, not peak memory, service memory, a shipping ceiling or evidence that all model-related memory returned to baseline. The four observed request durations were approximately 2.002, 1.576, 1.575 and 1.774 seconds; this uncontrolled sequence does not establish a causal speed improvement.

The raw log contains two BNNS execution-cache compilation diagnostics reporting **No space left on device**. They are preserved despite the official test result having no runtime warnings. Recognition and reuse still completed, but the effective backend/fallback mechanism and performance under normal cache conditions are unestablished. No replacement run or extra inference was performed.

Build, test and metadata collection closed with actual parent exit 0. The official result contains exactly one test, one configuration and one device, with zero failures or skips. The simulator ended Shutdown. Root checked 934 frozen source bindings, the generated project and build-product namespaces, preserved existing result bytes during metadata export, and observed all 14 owned process groups empty.
