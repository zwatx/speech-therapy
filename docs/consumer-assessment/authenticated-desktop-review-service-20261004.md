# Authenticated desktop review service — 2026-10-04

The isolated service at `research/assessment-review-service` adds local credential authentication, current project-role authorization, private generated-media delivery and recoverable mutation attribution around the [unchanged assessment workbench](../../research/assessment-workbench/README.md). It is a closed desktop engineering fixture built with standard-library Python and plain JavaScript/CSS. Its [operator guide](../../research/assessment-review-service/README.md) contains startup, export, administration and scoped verification commands.

## Included scope

The service accepts exactly two fixed source projects. The generated `demo-review` project has four invented participants, eleven attempts and nine present recordings, all mapped to the identical quiet 220 Hz, 1.2-second PCM16 mono 16 kHz waveform. Speech labels, reference answers and predictions are fabricated workflow metadata. The waveform tests transport and permissions, not pronunciation or accuracy. There is no real-media, arbitrary-manifest or model import.

The coordinator-only content-preparation project retains the existing public snapshot's 15 prompts, 17 pronunciation variants and 23 target occurrences, with byte-bound source identity and all initial content/task definitions pending. It has zero participants and attempts. Its engineering content records do not establish qualified approval, reference licensing or readiness for collection. Learner, clinical and production flags remain false throughout.

Four random invented credential accounts have separate historical coordinator, reviewer-a, reviewer-b and adjudicator slots. The server resolves each role from the current registry; request bodies cannot nominate a reviewer identity or role. Reviewers receive only their own blind projection, without source participant/split/model information or another reviewer's notes. Seals preserve both original rosters, and adjudication changes only the target decision after both seals. Local account separation does not establish different humans, clinical qualifications or independent review.

The private owned root/directories use `0700`, and credential, journal and waveform files use `0600`. Credentials stay in the operator-only fixture file; raw values are never printed or copied into this record. Fixed-cost scrypt checks, bounded login/session storage and a service-wide operation lock protect current account generation/assignment checks together with protected reads, mutations and audit work. Anonymous bootstrap sessions last 120 seconds; authenticated sessions expire at 15 minutes idle or 30 minutes absolute. Passive/failed requests do not extend idle life, and restart invalidates sessions.

Revocation and assignment deactivation are irreversible, including historical slot occupancy. Resetting an active password invalidates old sessions but cannot restore a revoked account. A new fixture root is required to repeat a workflow after irreversible account administration. Administrative commands and audit export are trusted OS-owner CLI operations; there is no HTTP account/role administration or HTTP audit export. CLI project export still checks the current fixed fixture coordinator slot and generation, without asserting a browser login.

## Restrictions and recovery

Current permission or withdrawal restrictions block new media and substantive original reviews. The exact canonical unavailable original marker remains admissible so the full roster can be sealed. All new adjudications are blocked when current recording/playback availability is absent. Previous reviews, adjudications and the full attempt denominator remain in history; affected attempts lose engineering admission. Already delivered or in-flight audio cannot be recalled. A media receipt documents an authorization/delivery attempt, not hearing or client receipt completion.

Mutation intent, source event and completion receipt occupy separate fsynced journals. They are not an atomic cross-file transaction. Reconciliation recognizes an unchanged source as not applied or an exact next source event as applied, and quarantines corrupt, unexpected or unaccounted history. An `operation_outcome_unavailable` response requires refresh/verification before a manual next-step decision; it does not justify rollback claims or blind retry.

Private project exports are replay-verified before exclusive `0600` writes to new files in existing owned `0700` parents. The separate audit export omits credentials, raw failed usernames, notes, ratings and prediction payloads. Browser download permissions follow the browser/OS destination and are not guaranteed owner-only. Hash chains and semantic source pins demonstrate consistency and replay correspondence, not signatures, encryption, authentic provenance or global chronology.

## Continuing from this fixture

Resume an existing private root with `serve`, and use `verify-service` before assessing interrupted-operation outcomes. A fresh `create-fixture` root restarts the closed invented workflow; it does not onboard real people or media. The [operator guide](../../research/assessment-review-service/README.md) includes exact two-root `PYTHONPATH` commands and safe exports/reset/revoke/deactivate examples.

The service remains a single-threaded loopback HTTP research tool. Exact Host/Origin, CSRF and bounded framing checks do not provide TLS, port isolation or a production security guarantee. A hostile local OS owner or other localhost servers are excluded from the threat model. Larger desktop work involving real-data onboarding, qualified reviewers, current permissions/reference licensing, prospective application-domain validation or deployment needs a separately authorized goal. Mobile remains paused and the reserved study remains sealed. No external publishing or outreach is part of this implementation.
