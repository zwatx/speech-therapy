# Word runtime reuse: controlled verification, 17 October 2026

The reusable word-recognition runtime and its session cleanup integration passed **183 controlled Debug tests** on the arm64 iPhone SE (3rd generation) simulator running iOS26.5. This checkpoint verifies lifecycle behavior with generated fixtures and controlled workers. It does not yet establish real-model reuse, lower latency or acceptable app memory use.

The implementation gives each bundled provider one lazy, serially owned encoder/decoder pair. Each request still performs full resource admission; audio handles, request tensors, prefixes and callbacks are not cached with the pair. Failed or mismatched admission invalidates reuse. Cancellation and the existing 15-second deadline retain their prior priorities, and confirmed worker/timer/borrow cleanup remains necessary. Explicit flow-end disposal joins the owned runtime; later explicit restart can load a fresh pair. Source contracts and limits are recorded in the [integrated source review](../../work/word-runtime-reuse-20261017/INTEGRATED-SOURCE-REVIEW.md).

The first controlled run exposed an actual integration regression: awaited recovery APIs could return before newly asynchronous runtime disposal completed. That run remains failed: **182 tests, 168 passed, 14 failed, 17 assertions**. The correction makes asynchronous end/recovery paths join the same pending disposal, including duplicate cleanup retry when ordinary retry eligibility is already false. Existing cleanup, mirror, file and transition-token gates remain in place; no failing assertion was weakened. The original test file is preserved, and one regression was appended. See the [original failed admission](../../work/word-runtime-reuse-20261017/units-v1/FAILED-RUN-ADMISSION.json), [correction review](../../work/word-runtime-reuse-20261017/recovery-fix-proposal/INDEPENDENT-REVIEW.md) and [held-retry test review](../../work/word-runtime-reuse-20261017/recovery-test-proposal/INDEPENDENT-REVIEW.md).

The fresh corrected run passed provider17, session154, runtime-owner4 and file-ownership8 tests, with zero failures, skips or expected failures. All14 previously failing methods passed. The new public recovery test holds disposal, verifies both the first and duplicate retry remain unfinished with actions gated, releases the fixture, and verifies both callers join one disposal. Its approximately0.002377-second test duration is controlled scheduling evidence, not model teardown latency.
