Approved security review of durable, privacy-minimized clinician token-generation limits that preserve emergency device revocation.

Context

The five-slot learner-device ceiling prevents unlimited active grants, but it does not bound repeated issuance or replacement attempts. This milestone adds a database-enforced abuse boundary before raw token generation without throttling the safety-critical revocation path. The implementation remains a local foundation: no managed PostgreSQL/Neon contention evidence, provider-edge control, or learner-device invalid-token/IP throttling is claimed.

Decision

Approved with no remaining code blocker. Issue and rotation consume one fixed UTC-hour budget at two scopes: 30 attempts per tenant/clinician actor and 10 attempts per tenant/learner. The ordered actor-then-learner upsert is atomic; a denial in either scope fails the request. Capacity conflicts count as attempts, while internal active-slot retries happen after a single budget consumption. Revocation does not call the limiter.

The API maps a blocked request to a private 429 response with database-derived Retry-After. The clinician UI states both limits and explicitly preserves revocation availability. Buckets retain only opaque internal scope IDs, aggregate counts, a request UUID, and timestamps—never raw tokens, token hashes, IP addresses, or clinical content. Learner-scoped buckets are deleted with the learner.

Independent review findings

The first review correctly blocked two details:

  1. date_trunc on TIMESTAMPTZ followed the database session timezone, so a non-UTC session could misalign windows and make UTC copy false. The final query explicitly converts to UTC before truncation and converts the boundary back to TIMESTAMPTZ.
  2. An opportunistic deletion CTE for old buckets had no guaranteed ordering relative to the upsert and could create an avoidable lock-order cycle. It was removed from the request path. Retention is now an explicit operations requirement instead of an unsafe inline side effect.

Re-review approved the corrected query. It also confirmed fail-closed partial consumption, one-count internal retries, counted capacity conflicts, and the revocation exemption.
