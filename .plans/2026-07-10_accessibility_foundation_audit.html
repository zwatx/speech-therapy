The automated accessibility foundation is ready to retain as a release guard; it found and drove real fixes, but it is not a conformance certificate or a substitute for disabled-participant and assistive-technology testing.

Verdict: approve the automated foundation. Playwright + axe and native XCTest audits are green, focus and status semantics are materially stronger, and the audit fixtures do not weaken production authorization. Keep the product accessibility gate open until the manual matrix is complete.

Scope

The review covers the Next.js clinician shell, access boundary, representative dashboard/table/safety/form states, and the SwiftUI enrollment and ready-practice screens. The target standard is WCAG 2.2 A/AA plus Apple Dynamic Type and native accessibility guidance. Automated states include desktop, keyboard-only skip behavior, 390-pixel mobile, reduced motion, Windows forced colors, enrollment, and ready practice.

Verification

  • pnpm test:a11y — four Playwright tests pass; three run WCAG A/AA axe scans with zero detectable violations and one verifies keyboard focus transfer.
  • pnpm test:ios — 36 native unit tests plus two platform accessibility UI audits pass on iPhone 17 Pro simulator.
  • pnpm typecheck, pnpm lint, pnpm test:js, Swift contract tests, and pnpm build pass.
  • A production server returns HTTP 404 for /accessibility-preview; the route needs both a non-production runtime and an explicit audit environment variable. The iOS practice fixture is compiled only in Debug and has no submitter.
  • An independent read-only review approved the accessibility and authorization boundaries with no blocking finding.

Required before pilot

  1. Run every authenticated clinician workflow with VoiceOver/Safari, NVDA/Firefox or Chrome, and JAWS/Chrome.
  2. Run every learner phase on physical iPhone/iPad with VoiceOver, Voice Control, Switch Control, all accessibility Dynamic Type sizes, Bold Text, Increase Contrast, Reduce Motion, and supported orientations.
  3. Complete task-based sessions with disabled clinicians, caregivers, and children; severity-rate, remediate, and retest every barrier.
  4. Record device, OS, browser, assistive-technology version, task, result, evidence, owner, and retest state. Do not label an automated zero-finding run as WCAG certification.
