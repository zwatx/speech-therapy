Approved review of durable valid-device request budgets for assignment reads and audio uploads, including native Retry-After behavior.

Context

Clinician token generation is bounded, but a valid enrolled token previously allowed unmetered assignment polling and audio-upload requests. The milestone adds a database abuse boundary after valid-device authentication. It intentionally does not claim invalid-token or IP protection because trustworthy client address attribution depends on the eventual deployment provider.

Verdict

Approved with no blocking security or correctness finding. Migration 0025 creates a dedicated table keyed by tenant, device session, operation, and UTC-hour window. Assignment reads and attempt uploads each receive 120 requests per valid session per hour. One statement rechecks the live slot, expiry, learner deletion, exact current consent, audio permission, and assent before atomically consuming the relevant bucket.

Behavior reviewed

  • Invalid tokens and the explicit internal resolver create no request bucket.
  • Every current learner assignment/upload handler calls operation-aware authorization with a hard-coded operation; runtime-unknown operations fail before database access.
  • One operation cannot consume the other's capacity, and two device sessions remain independent.
  • The first policy stored in a live window is frozen until the next UTC boundary, avoiding unsafe mid-window limit changes.
  • Every HTTP retry or idempotent replay consumes another request. The 120-upload budget equals twice the maximum 20 × 3 attempt dose, allowing one replay per slot.
  • A composite foreign key cascades buckets with session deletion. Revoked-session aggregates remain until retention or learner deletion.
  • Private 429 responses include database-derived Retry-After. iOS accepts only numeric 1–3600 second values, preserves enrollment, rounds conservatively, and falls back to generic rejection for unsafe headers.

Required before deployment

  • Rehearse migration 0025's table lock, unique constraint, and composite foreign key on the target managed PostgreSQL/Neon environment.
  • Stress same-bucket boundary contention, two operations, authorization versus revoke/rotate/delete/consent changes, and exact UTC rollover.
  • Add trusted provider-edge invalid-token/IP throttling and network/log privacy evidence.
  • Deploy an operations-owned bounded retention workflow for inactive aggregate buckets.
