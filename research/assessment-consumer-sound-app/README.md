## Explicit startup inputs

Use the existing pinned Python3.13 environment, with this directory on PYTHONPATH, and `-m consumer_sound_app.launcher`. All inputs are mandatory:

- `--port`: a separate loopback port;8782 is refused.
- `--runtime-root`: a new owned root; word and phone subdirectories share the original executor's resource/cleanup ownership.
- `--cache-dir`: the separately reviewed existing checkpoint cache; no download or alternate model path is added.
- `--feature-source-sha256`: the new canonical source-inventory SHA in the integration receipt.
- `--worker-artifact-dir`: the explicit existing frozen artifact directory.
- `--worker-source-sha256`: exact reviewed e392 source SHA.
- `--worker-receipt-sha256`: exact reviewed 0c1762 receipt SHA.

There is no default work-path loader, fallback, implicit cache download or alternate encoder. `WorkerArtifact` rejects unknown/extra configuration and unreviewed hashes even through direct construction. It reads bounded owned regular files with NOFOLLOW|NONBLOCK and verifies receipt, supervisor and source-pins hashes before loading the stdlib-only supervisor. It executes verified source bytes rather than an unbound timestamp-based Python cache, checks the frozen full snapshot and rechecks artifact metadata. No acoustic/native runtime is imported until the explicit model action.

The frozen supervisor derives its repository root from its artifact layout and its source map retains original relative paths. This package therefore requires that exact existing artifact layout within this checkout. It derives the precise artifact directory from the pinned supervisor source-map entry and verifies the colocated worker.ts bytes before executing any supervisor source; matching files copied to another same-depth directory are refused. Unsupported relocation fails explicitly. The artifact is not recopied or repinned; a portable worker distribution would require a separate reviewed source/runtime migration. The explicit artifact path is private launcher configuration, not public response content.

Complete source and artifact verification precedes Catalog, runtime and listener construction. Original Catalog initialization verifies public references only at root's separately authorized actual launch; the implementation tests use its real accepts method with frozen metadata and never invoke its media-reading constructor. Startup tests exercise refusal paths only; no real server was launched by the implementation agent.
