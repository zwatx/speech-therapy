# Intended-recording validation preparation

This tool implements a fixed prospective **admission and reference-feasibility** protocol. It does not recruit, record, contact reviewers, open the reserved study or validate pronunciation. Professional review remains a finished-product handoff, as the owner requested. The existing content overlay is the engineering baseline; historical pending packets remain unchanged.

The complete operational design has 210 independently sampled participants, one per household, ages 6–12, each with one preassigned first positive and one first challenge attempt. This is a prospective engineering precision design, not an authorized collection quota or clinical standard. It evaluates the fixed 13-word vocabulary on new households; no unfamiliar-word generalization is claimed. Model, policy, content and primary allocation hashes must be frozen before intended-recording evaluation. Recruitment, actual permissions, independent humans and qualification remain factual external inputs.

The primary positive endpoint requires determinate independent reference evidence of usable speech containing the requested word and system admission. Safe challenge handling requires a determinate reference matching the preassigned wrong-word, extra-word or nonspeech challenge type and an evidenced system rejection. Replacing a preassigned extra/wrong-word challenge with easier nonspeech is an explicit allocation mismatch and cannot count as safe handling. Missing recordings, unresolved references and failures are unsuccessful primary outcomes. An observed unsafe admission is reported separately from inability to establish safe handling. A retry never replaces a preassigned index attempt.

Engineering criteria require exactly the 210 declared evaluation household units, a two-sided 95% Wilson lower bound of at least 90% for confirmed positive admission, an upper bound of at most 5% for conservative challenge failure, no unresolved original disagreement, and valid household isolation. These defaults are an engineering study decision, not a clinical benchmark. With 210 independent units, 198 successes have a lower bound of about 90.28%; zero failures have an upper bound of 1.80%, four about 4.79%, and five about 5.45%. Thirty subgroup units with zero failures still have an upper bound of 11.35%. These are planning calculations, not observed performance. Formula: [NIST confidence intervals](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm).

Intervals are conditional on the declared independent binomial sampling design. Unknown identity/household linkage, multiple participants in one household, household partition conflicts cross-partition recording overlap, reused primary recording bytes and pending permission/reviewer evidence suppress them. Age, variety, word and condition counts remain descriptive; repeated tokens receive no independent-binomial interval. Shared vocabulary means the declared split isolates people and households, not words. Pretrained-data overlap remains unknown.

## Run privately

From the repository root, set only these scoped import paths. Python's standard library suffices; no root build or mobile command is involved.

```sh
export PYTHONPATH=research/assessment-intended-validation:research/assessment-workbench:research/content-review-preparation
python3 -m intended_validation prepare /absolute/owned-parent/new-preparation MODEL_MANIFEST_SHA256 ADMISSION_POLICY_SHA256
python3 -m intended_validation report /absolute/private/protocol.json /absolute/private/observations.json /absolute/private/new-report.json
python3 -W error -m unittest discover -s research/assessment-intended-validation/tests
```

`prepare` exclusively creates an owned 0700 directory and three 0600 files: protocol, empty observation bundle and preparation report. No participants or original labels are fabricated. Inputs/outputs use the already-reviewed strict bounded private-file and JSON helpers: absolute paths, no symlink components, owned 0700 parent, regular single-link 0600 files, 8 MiB limit, no duplicate keys/nonfinite values, exclusive outputs. Console summaries omit supplied observations and notes. These controls are local consistency and privacy, not encryption or provenance authentication.

Preparation binds the empty allocation and participant roster. For a later separately authorized intended-recording study, use `make_protocol_v2(model_manifest_sha, policy_sha, semantic_digest(allocation), semantic_digest(participants))` to freeze the actual allocation and complete participant roster (including partition and household linkage) **before recording/model use**, and retain its reviewed dated declaration independently. Each allocation row contains participant `id`, `positiveAttemptId`, `challengeAttemptId`, `positivePromptId`, `challengePromptId`, and `challengeType` (`wrong_word`, `extra_word`, `nonspeech`). Merely recomputing a hash after seeing results does not establish chronology or preassignment.

The supplied bundle uses `mode: supplied_observations`, an explicit sampling-independence declaration, that exact allocation, participants, every initiated attempt, three reviewer records, two original reviews for every attempt and any adjudications. `invented_exercise` exercises the report without enabling intended-recording intervals. Source schemas and allowed values are the small pure protocol/report modules. Binding hashes check correspondence, not whether records or people are genuine.

Two later qualified people provide separately blinded originals. Original observations include quality, speech presence, requested/other/extra word, variant, occurrence observability and target label. Prediction/challenge/source/identity and the other reviewer are withheld under the documented process. Reviewer identity, qualification, conflict and blinding evidence references must be factual; null references are valid pending declarations and suppress intended-recording intervals; account IDs or supplied SHA values alone cannot verify them. Adjudication binds both immutable original hashes and resolves the **complete observation vector**, preserving originals. Explicit uncertain/unavailable observations count; literally missing rows, foreign IDs, changed audio/policy/content, invalid occurrences and contradictory ancestry fail.

Phone correctness is excluded from this protocol: the old three-class corpus predictor has no justified mapping to a correctness decision. `phoneDecisionEvaluation` remains `not_evaluable`. All learner, clinical, production, qualified-review, authentic-provenance and meaningful-improvement flags remain false even if engineering criteria are met. Passing this report is not a release approval.

Planned new-recording repeats are linked by participant, word, variant and occurrence, with declared conditions and a 24-hour to seven-day interval. Missing pairs and deviations remain reported. Identical audio bytes are a computational replay; a post-practice observation is not automatically improvement. No meaningful-change threshold is invented.

Observed verification: 26 focused checks pass with warnings treated as errors, including actual private CLI preparation/report, exclusive-output refusal, malformed/private-file rejection, primary allocation binding, stale original/adjudication hashes, unknown linkage, missing reviews, invalid occurrence/age, retry misuse and repeated-byte rejection. Intended-child data collection and performance verification have not run.
