# Simulator speech admission service

This separate, optional loopback service connects the Debug iOS simulator lab to the frozen independent speech/requested-word admission module. Ordinary local practice works without a service or account. The old speech-check service on8765 remains available with its original contract. No production, learner-feedback, clinical, phonetic correctness, overall-score or movement claim is enabled.

Start from the repository root, using the existing full research environment:

```sh
PYTHONPATH=research/assessment-mobile-admission:research/assessment-admission:research/audio-head \
  research/audio-head/.venv/bin/python -m mobile_admission.service
```

The address is fixed at `http://127.0.0.1:8778/v1/admission`. No other interface, destination, port argument, redirect or browser origin is supported. Four bounded handlers share one inference slot. HTTP reads have a five-second deadline; request bodies are at most200000bytes, decoded WAV at most132096bytes, public responses at most16000bytes. The outer trusted-worker timeout is85seconds; the native request/resource timeouts are100/105seconds. A disconnected client may leave processing running until completion/timeout. The socket service records no request logs or retained attempt ledger.

In a Debug simulator app, open About → **Speech admission lab**, read the optional-processing explanation, choose a completed age6–12 and a word, and explicitly enable local processing. Record still requires a separate tap. The old **Speech check lab** uses8765. For launch verification, `-CadenceAssessmentMode -CadenceAdmissionMode` opens the admission route. Both menu entries are absent on physical devices and Release; the new transport is also excluded from those builds. This work did not activate a microphone, camera or playback during verification.

The request has exactly `{schemaVersion:1,attemptId,ageYears,prompt,audioBase64}`. The UUID is caller-owned and lowercase; schema2prompt uses the existing frozen prompt builder, binding every selected occurrence and dictionary variant. No path, source name, model hint, transcript/history context, or arbitrary URL enters the request. The bytes-only recognizer independently runs Silero and Whisper before the frozen research bridge. The pinned models and declared policy are unchanged; no challenge study is rerun or tuned here.

The response has exactly `schemaVersion`, `researchOnly`, `status`, `reason`, `speechAdmissionPassed`, `wordAdmissionPassed`, `researchProcessed`, `bridgePromptMatch`, `claimLimits`, `elapsedMilliseconds`, and `binding`. `processed` requires all three engineering processing flags true and a verified bound research envelope; unavailable clears all three. The old bridge match remains `unverified`. All nine claim limits remain false. Exact request/audio/canonical-prompt SHA-256, admission-model manifest, semantic policy, frozen-admission/bridge source maps, new-service source map, and owned-supervisor SHA-256 must match the native pins. Transcripts, selected-token/window probabilities, research probabilities and private paths are omitted. The native client rejects unexpected evidence fields or missing/mismatched bindings/flags and refuses redirects. Source correspondence does not establish signed or authentic provenance.

The isolated worker overlays only the frozen adapter's temporary staging directory onto its caller-owned private stage, without changing frozen source/model/policy bytes. The frozen bridge uses that stage through `TMPDIR`. The new service vendors a reviewed owned supervisor rather than importing a moving desktop implementation. Its initial exact desktop copy and the subsequent mobile correction are preserved separately: the correction normalizes process start-stamp padding, retries one transient process scan within existing deadlines, attempts owned-tree cleanup after a monitor failure, and retains fixed private failure/scan metadata. The original actual failure cause remains unknown; these are independently exercised protective fixes. It tracks the trusted nested worker tree and confirms bounded cleanup. This is local trusted-worker supervision, not atomic PID ownership or adversarial containment.

A700/600 runtime owner lock prevents two service owners. A fsynced `cleanup-required` intent precedes every worker launch; it is cleared only after confirmed descendant cleanup, removal of the private stage and directory synchronization. Uncertain worker cleanup, failure to persist the prelaunch cleanup intent, or failed stage deletion latches the owner blocked and preserves a private stage/intent. A monitor failure discards the result even if subsequent cleanup is confirmed. One bounded private runtime diagnostic retains timing, exit, scan and tracked PID/start-stamp metadata without request/audio/transcript/arguments/environment. If only that diagnostic write fails after confirmed worker and file cleanup, the result is unavailable and another attempt is allowed; safe-cleaned audio is not retained for a diagnostic failure. Reopening with an intent or interrupted stage refuses further inference. Automatic recovery does not delete evidence or risk killing unrelated processes. An owner must stop the service, independently confirm no trusted worker descendants remain, and remove only the service's private runtime artifacts before intentionally reopening. Abrupt host/owner death can bypass cleanup; removal cannot be guaranteed, and restart blocking is the recovery barrier. Secure erasure and backup recall are unestablished.

Native processing/cancellation/background/interruption/close uses the existing invalidation-before-deletion flow. Late callbacks cannot revive discarded attempts; client cleanup failure blocks capture and never claims deletion. The in-memory100-row ledger adds internal admission-processed/rejection/service-cleanup reasons; it stores no prompt, age, identity, audio, transcript or probabilities. Each started attempt retains one terminal outcome, retry links and lifetime counts. The UI still offers retry or ordinary practice and shows no pronunciation finding after admitted processing.
